# InterviewIQ - Render.com Deployment Guide

This guide will help you deploy InterviewIQ to Render.com with PostgreSQL database support.

## Prerequisites

1. A Render.com account (sign up at https://render.com)
2. Your Google Gemini API key (get it from https://aistudio.google.com/app/apikey)
3. Git repository with your InterviewIQ code

## Quick Deploy with render.yaml

### Option 1: Automatic Deployment (Recommended)

1. **Fork or push this repository to GitHub**

2. **Connect to Render**
   - Log in to your Render dashboard
   - Click "New +" → "Blueprint"
   - Connect your GitHub repository
   - Render will automatically detect `render.yaml` and set up both the web service and database

3. **Configure Environment Variables**
   
   After deployment is initiated, you'll need to set these environment variables:
   
   - `DATABASE_URL` - Auto-configured by Render when you link the database
   - `GEMINI_API_KEY` - Your Google Gemini API key
   - `SESSION_SECRET` - Auto-generated by Render (or set your own secure random string)
   - `NODE_ENV` - Set to `production` (already configured in render.yaml)

4. **Database Setup**
   
   After the first deployment:
   - SSH into your Render shell or use Render's shell access
   - Run database migrations: `npm run db:push`

5. **Access Your App**
   - Your app will be available at: `https://interviewiq.onrender.com` (or your custom domain)

### Option 2: Manual Deployment

If you prefer to set up services manually:

#### Step 1: Create PostgreSQL Database

1. In Render Dashboard, click "New +" → "PostgreSQL"
2. Name: `interviewiq-db`
3. Database Name: `interviewiq`
4. Plan: Choose your plan (Starter is fine for testing)
5. Click "Create Database"
6. Copy the "Internal Database URL" for later

#### Step 2: Create Web Service

1. Click "New +" → "Web Service"
2. Connect your repository
3. Configure the service:
   - **Name**: `interviewiq`
   - **Runtime**: `Node`
   - **Build Command**: `bash scripts/build.sh`
   - **Start Command**: `npm start`
   - **Plan**: Choose your plan (Starter is fine for testing)

#### Step 3: Environment Variables

Add these environment variables to your web service:

| Variable | Value | Notes |
|----------|-------|-------|
| `NODE_ENV` | `production` | Required |
| `DATABASE_URL` | [Internal Database URL] | Copy from database you created |
| `GEMINI_API_KEY` | [Your API Key] | Get from Google AI Studio |
| `SESSION_SECRET` | [Random String] | Generate a secure random string (32+ chars) |

#### Step 4: Deploy

1. Click "Create Web Service"
2. Wait for the build to complete (5-10 minutes first time)
3. Once running, open the Shell tab in Render
4. Run: `npm run db:push` to set up database schema

## Environment Variables Reference

### Required Variables

- **`DATABASE_URL`**: PostgreSQL connection string
  - Format: `postgresql://user:password@host:port/database`
  - Automatically provided by Render when you connect a PostgreSQL database
  
- **`GEMINI_API_KEY`**: Your Google Gemini API key
  - Get it from: https://aistudio.google.com/app/apikey
  - Used for CV analysis, interview feedback, and course recommendations
  
- **`SESSION_SECRET`**: Secret key for session encryption
  - Generate with: `openssl rand -hex 32`
  - Must be a secure random string (minimum 32 characters)

- **`NODE_ENV`**: Environment mode
  - Set to: `production`
  - Controls production vs development behavior

### Optional Variables

- **`ADMIN_SEED_TOKEN`**: Token for accessing demo data seeding endpoints
  - Only needed if you want to seed sample data via API
  - Auto-generated in development if not set

- **`PORT`**: Server port
  - Default: `5000`
  - Render automatically sets this, no need to configure

## Build Process

The build process consists of two steps:

1. **Frontend Build** (Vite)
   - Compiles React TypeScript code
   - Bundles with optimizations
   - Outputs to: `dist/public/`

2. **Backend Build** (esbuild)
   - Bundles Express server code
   - Handles TypeScript compilation
   - Outputs to: `dist/index.js`

Build command: `bash scripts/build.sh`

## Database Schema Deployment

After your first deployment:

```bash
# SSH into Render shell
npm run db:push
```

This will:
- Create all necessary tables (users, cv_analyses, mock_interviews, user_progress, interview_sessions)
- Set up foreign key relationships
- Configure indexes and constraints

## Troubleshooting

### Build Failures

**Error: "Cannot find module..."**
- Ensure all dependencies are in `dependencies` (not `devDependencies`)
- Run `npm install` locally to verify package.json is correct

**Error: "Build script not found"**
- Verify `scripts/build.sh` exists and is executable
- Check file permissions: `chmod +x scripts/build.sh`

### Runtime Issues

**500 Error on API calls**
- Check environment variables are set correctly
- Verify `DATABASE_URL` is the Internal Database URL from Render
- Check logs in Render dashboard for specific errors

**Database connection errors**
- Ensure PostgreSQL database is running
- Verify `DATABASE_URL` environment variable
- Run `npm run db:push` to ensure schema is deployed

**AI features not working**
- Verify `GEMINI_API_KEY` is set correctly
- Check API key has not expired
- Review Gemini API quotas and limits

### Session/Authentication Issues

**Users can't log in / sessions expire immediately**
- Verify `SESSION_SECRET` is set
- Ensure it's a sufficiently long random string (32+ characters)
- Check database session store is working

## Scaling Considerations

### Course Recommendation Cache

The course recommendation service uses in-memory caching (24-hour TTL). For multi-instance deployments:

- **Current**: In-memory cache works for single instance
- **Scaling**: Consider adding Redis for distributed caching when scaling horizontally

### Database Connection Pooling

The app uses Drizzle ORM with Neon's serverless driver which handles connection pooling automatically. No additional configuration needed.
